# Agent Service Protocol (v1)

The boundary between the Python engine and its clients (headless TUI today,
the SwiftUI shell tomorrow). It is the only stable interface: a pure-Swift
engine can replace the Python one later with zero UI change, so **every type
crossing this socket must be expressible as a Swift `Codable` struct.**

Status: v1 implemented in `openagent/service/protocol.py`.
`tests/service/test_contract_fixtures.py` asserts the Python implementation
matches this document; the Swift package replays the same JSON fixtures.

---

## 1. Transport

- **Unix domain socket**, one process, one user. No TCP, no auth layer — the
  socket file is the credential (`0600`, owner-only).
- **NDJSON framing**: one JSON object per line, `\n` terminated, UTF-8, no
  embedded raw newlines (JSON escapes them). Max frame **8 MiB**
  (`MAX_FRAME_BYTES`); a larger frame is a protocol error and closes the
  connection.
- **JSON-RPC 2.0** envelope: `{"jsonrpc":"2.0","id":...,"method":...,"params":{...}}`.
  A message with `method` and no `id` is a notification (no response).
- `id` is a string, generated by the client and echoed by the server. **All
  requests are client→server in v1.** The one reverse channel — tool approval —
  is a `permission_requested` *event* plus a `permission.respond` *request*
  carrying its `request_id`, so the socket never carries two directions of
  request and needs no id namespacing. Keep it that way: bidirectional
  JSON-RPC on one socket is how deadlocks get written.

### Naming convention (deliberate asymmetry)

- **Methods** are dotted, camel-free: `run.start`, `model.list`, `auth.status`.
  New in v1, so they set the convention.
- **Events** keep the exact `type` literals of `openagent.runtime.events`
  (`run_started`, `message_delta`, `tool_call_completed`). Those literals are a
  pre-existing Python contract with 463 tests behind them; the wire reuses them
  so a runtime event serializes 1:1 with `dataclasses.asdict`.
- **Field names are snake_case** on the wire. Swift decodes with
  `JSONDecoder.keyDecodingStrategy = .convertFromSnakeCase`. Do not "fix" this
  to camelCase: it would break the 1:1 mapping and every fixture.

## 2. Handshake

Client's first call **must** be `hello`:

```jsonc
→ {"jsonrpc":"2.0","id":"c1","method":"hello","params":{"protocol_version":1,"client":"solocoder-tui","client_version":"0.1.0"}}
← {"jsonrpc":"2.0","id":"c1","result":{"protocol_version":1,"min_protocol_version":1,
     "server":"openagent","server_version":"0.1.0",
     "methods":["hello","run.start",…],"events":["run_started","message_delta",…],
     "terminal_event_types":["run_cancelled","run_completed","run_failed"],
     "permission_modes":["allow_all","allow_readonly","ask"]}}
```

A `protocol_version` the server cannot serve is `PROTOCOL_MISMATCH` (-33008)
and the connection closes. Every other method before `hello` is
`INVALID_REQUEST`.

`terminal_event_types` is the set of events that end a run's stream. A client
treats **the union of its own set and the server's** as terminal: the
connection stays open after a run (the client keeps using it), so a terminal
event a client has never heard of would otherwise leave its stream waiting
forever. A new terminal event type is therefore additive, not breaking.

## 3. Methods

| Method | Params | Result |
| --- | --- | --- |
| `hello` | `protocol_version`, `client`, `client_version` | handshake above |
| `ping` | — | `{"pong": true, "server_time": float}` |
| `run.start` | `prompt` (str), `working_dir` (str, **required**, absolute), `model` (str, optional `provider/model`), `session_id` (optional), `max_turns` (int), `permission_mode` (`allow_all`\|`allow_readonly`\|`ask`), `images` ([base64], optional), `reasoning_effort` (`none`\|`minimal`\|`low`\|`medium`\|`high`\|`xhigh`\|`max`, optional) | `{"run_id": …, "session_id": …, "model": "provider/model"}` |
| `run.cancel` | `run_id` | `{"cancelled": true}` (the `run_cancelled` event follows on the stream) |
| `run.permission_mode` | `run_id`, `permission_mode` | `{"run_id": …, "permission_mode": str}` — changes the live run’s gate and file-tool scope |
| `permission.respond` | `request_id`, `granted` (bool), `scope` (`once`\|`session`\|`never`) | `{"ok": true, "granted": bool, "scope": str}` |
| `model.list` | `discover` (bool) | `{"models":[ModelRef…], "policy":…, "default_model":…, "selected":…}` |
| `model.probe` | `model` | `{"ok":bool,"latency_ms":int,"tools":bool,"detail":str}` |
| `model.select` | `model` | `{"default_model": …}` |
| `model.add_endpoint` | `name`, `base_url`, `wire_api` (`openai-chat`\|`openai-responses`\|`anthropic-messages`\|`ollama-chat`\|`gemini`), `label` (optional), `local` (bool), `requires_key` (bool), `tools` (bool), `context_window` (int) | `{"endpoint": {…}, "models": [ModelRef…], "discovery_error": str\|null}` — persists the endpoint and discovers it in one call |
| `model.remove_endpoint` | `name` | `{"name": …, "removed": bool}` — built-in endpoints are refused |
| `auth.status` | — | `{"providers":[…], "servers":[…]}` (same rows as `cli_coder auth status`) |
| `auth.logout` | `provider` | `{"ok": true}` |
| `auth.login` | `provider` | `NOT_IMPLEMENTED` in v1 — needs an interactive browser, keep it in the CLI |
| `tool.list` | — | `{"tools":[{"name","description","risk","requires_permission"}]}` |
| `session.list` | — | `{"sessions":[{"session_id","path","updated_at","message_count"}]}` |
| `session.load` | `session_id` | `{"session_id":…, "messages":[…], "system_prompt":…, "context_tokens":…}` |
| `session.save` | `session_id`, `path` (optional) | `{"path": …}` |
| `config.get` | `keys` ([str], optional) | `{"config": {…}}` (secrets never included) |
| `config.set` | `values` (object) | `{"config": {…}}` |
| `browser.show` | — | `{"open": bool, "headless": bool, "url": str, "pid": int}` — brings the agent's browser forward for the user to take over; `pid` is its process (0 unknown), for the client to activate |

`run.start` **occupies the connection**: the server streams events for that run
on the same socket until a terminal event. `run.cancel` and
`permission.respond` are answered while a run is in flight. A second
`run.start` on a busy connection is `INVALID_REQUEST`.

### Session scope

`working_dir` is required and is the **only** way scope is set. The engine maps
it to `ToolContext`; the model only ever writes paths. The server refuses:

- relative paths, `~`, `/`, and the process CWD default;
- non-existent directories;
- paths outside the server's `--root` allow-list (empty allow-list = any
  absolute path, which is what a developer machine wants; a shipped app passes
  roots).

Denial is `WORKING_DIR_DENIED` (-33005) as a **response**, not an event — the
run never started.

## 4. Events

Emitted on the connection that started the run, as JSON-RPC **notifications**:

```jsonc
{"jsonrpc":"2.0","method":"event","params":{"type":"message_delta","run_id":"run_ab12","message_id":"msg_cd34","delta":"Writing…"}}
```

`params` is the runtime event dataclass verbatim. Every event carries `type`
and `run_id`.

| `type` | Fields (besides `type`, `run_id`) |
| --- | --- |
| `run_started` | — |
| `message_started` | `message_id` |
| `message_delta` | `message_id`, `delta` |
| `reasoning_delta` | `message_id`, `delta` |
| `message_completed` | `message_id`, `output_text` |
| `message_failed` | `message_id`, `error` |
| `tool_call_started` | `message_id`, `tool_call_id`, `tool_name`, `arguments` |
| `tool_call_completed` | `message_id`, `tool_call_id`, `tool_name`, `result` |
| `tool_call_failed` | `message_id`, `tool_call_id`, `tool_name`, `error` |
| `permission_requested` | `request_id`, `tool_name`, `arguments`, `reason` |
| `permission_resolved` | `request_id`, `granted`, `scope`, `reason` |
| `context_compaction_started` | `reason` |
| `context_compaction_completed` | `reason` |
| `context_compaction_failed` | `reason`, `error` |
| `context_usage` | `used_tokens`, `context_window`, `compact_at` |
| `run_completed` | `final_message_id`, `result{run_id, final_message_id, output_text, stop_reason}` |
| `run_failed` | `error` |
| `run_cancelled` | `reason` |

Ordering guarantees the UI is written against:

1. `run_started` is first; exactly one of `run_completed` / `run_failed` /
   `run_cancelled` is last, and nothing follows it.
2. `message_started` precedes every `message_delta` for that `message_id`;
   `message_completed`/`message_failed` closes it.
3. `tool_call_started` precedes its `tool_call_completed`/`tool_call_failed`.
4. A tool call that needs approval emits `permission_requested` **before**
   `tool_call_started`. A denied call emits **no** `tool_call_started`; the
   denial goes back to the model as an errored tool result.
5. `stop_reason` is `end_turn` | `max_turns` | `empty_response`.
6. `reasoning_delta` is the model's private thinking, streamed **before** the
   answer's `message_delta` for the same `message_id`. It is not part of the
   answer, never part of session history, and never sent back to the model. A
   client that ignores it shows a spinner that has not moved for ten seconds:
   measured on a reasoning model, ~1,900 reasoning tokens arrive before the
   first answer character. Render it as progress, in a subdued style, and close
   it when the answer starts.
7. `reasoning_effort` on `run.start` asks the provider how much thinking to
   allow. It is per-run and applies to every turn of it. `none` is not a
   cosmetic choice: measured on one reasoning model, the default spent 686,439
   characters on private reasoning and produced no answer at all, while `none`
   answered in 1.1 seconds. An unknown value is `INVALID_PARAMS`, and so is a
   value outside the model's `caps.reasoning_efforts` when that list is
   non-empty (the error data carries `supported`). An empty list means the
   server did not say; a client then offers its generic levels.

8. `browser_frame` (`run_id`, `data` base64 JPEG, `url`, `title`, `width`,
   `height`) is the agent's browser, live, on a service started with
   `--browser-use`. Chromium screencasts only while the page changes; the
   service sends at most ~4 a second and only the newest — a client that falls
   behind skips frames, never replays them. It is not conversation: keep it out
   of the transcript, and do not let it flush buffered deltas.

9. `context_usage` comes before each `message_started` and once more before
   `run_completed`. `used_tokens` estimates the next request — history, system
   prompt and tool schemas; `compact_at` is where the history gets summarised;
   `context_window` is the model's window, read from a llama.cpp server's
   `/props` when it has one. The two window fields are null when the window is
   unknown. `session.load`'s `context_tokens` is the same estimate, for a
   session that has not run yet. Like `browser_frame`, it is not conversation.

## 5. Tool approval

```
← event  {"type":"permission_requested","run_id":"run_ab12","request_id":"req_9f8",
          "tool_name":"bash","arguments":{"command":"rm -rf build"},
          "reason":"exec: runs arbitrary commands"}
→ {"jsonrpc":"2.0","id":"c7","method":"permission.respond",
   "params":{"request_id":"req_9f8","granted":true,"scope":"session"}}
← {"jsonrpc":"2.0","id":"c7","result":{"ok":true,"granted":true,"scope":"session"}}
← event  {"type":"permission_resolved","run_id":"run_ab12","request_id":"req_9f8",
          "granted":true,"scope":"session","reason":"approved by the user"}
← event  {"type":"tool_call_started", …}
```

The rules that make this safe:

- `permission_requested` is emitted **before** the engine blocks on the answer.
  Emit it after and the run deadlocks: the client only learns what to approve
  from the event.
- The server **fails closed**: no `permission.respond` within
  `permission_timeout` (default 60 s) is a denial, and the reason says so.
- `permission_resolved.reason` carries *why* the answer is what it is — the
  user refused, a session grant was reused, nobody answered in time. "Denied"
  and "denied because the prompt timed out" are different lines in a UI, and a
  silent timeout is the difference between a hung app and a refused tool.
- A denial emits **no** `tool_call_started`. The refusal goes back to the model
  as an errored tool result, so it can change course instead of crashing.
- `scope` is `once` (this call), `session` (this tool, rest of the run —
  answered silently from then on), `never` (deny and stop asking for this tool).
- Risk is derived from the **tool name**, never from the model's description of
  its intent (`openagent/runtime/permissions.py`). An unknown tool is
  `exec`-grade: fail closed.

not as an RPC error — the `run.start` response already succeeded.

## 7. Versioning

`PROTOCOL_VERSION` is bumped on any breaking change to a method's params, an
event's fields, or the framing. Additive changes (new method, new optional
param, new event type) do not bump it; clients must ignore unknown `type`
values and unknown fields — that is the whole reason `Codable` schemas are
written with `decodeIfPresent`.

## 8. Deliberate limits (v1)

- **No mid-run resume.** Reconnect = `session.load` + a new `run.start`. A
  durable event journal is a real feature, not a patch.
- **No multi-tenancy.** One user, one socket, one engine.
- **`auth.login` stays in the CLI** — an OAuth loopback browser flow cannot be
  driven from a socket client.
- **Cancellation is cooperative** at turn and tool boundaries; a blocked
  provider call is cancelled when it returns.
